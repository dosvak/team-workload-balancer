# Team Workload Balancer (TWLB) - process application

Who has what: open tasks grouped per person (or per team for unassigned tasks) with the overdue count, the age of the oldest task and the applications involved; click a person to list their tasks; reassign selected tasks to another user or group, or return them to their team; CSV.

Package `Team-Workload-Balancer-1.0.twx` (generated by `tools/build_twlb.py` on twxkit + kitlib, standard library only, no base export); targets: 8.6.2, BAW 24-26 (classic v1 API).
Vanilla BAW: UI Toolkit controls only, one client-side human service, server-side service flows calling the REST API with the technical
user of the environment variables. Import through the Process Center / Workflow Center console (`pc_import.py`) or Studio, set the
environment variables of the snapshot, open the dashboard from Process Portal or the playback URL of the `.ids.json`.

## Dashboard

| Tab | Content |
|---|---|
| Workload | criteria (application, team name part), Refresh; table per person / team (row click lists the tasks); task table (multi-select) with Reassign selected (modal), Return selected to their team, Export CSV |

Every list has a status line; errors open a message modal; CSV export shows the text in a modal for copy / paste.

## Service flows and REST calls

| Flow | Does |
|---|---|
| TW Init | header |
| TW Workload | `PUT /search/query` byTask (open tasks, optional application condition, sort taskReceivedDate) grouped server side by `assignedToUser`, else `(unassigned) <team>`; `who` in the input restricts the task list to one group |
| TW Reassign | `PUT /task/{id}?action=assign&toUser=` | `&toGroup=` | `&back=true` (no user and no group = back to the team) |
| TW Rows To CSV | task rows -> CSV |

## Environment variables

`serverBaseURL`, `restAuthUser`, `restAuthPassword`, `restTrustAllCertificates` (kit-rest.js: the technical user every server-side flow calls the REST API with), `appTitle`.

## Business objects

TWQuery (application, team, who), TWUser (who, open, overdue, oldestHours, apps), TWRow (task fields), TWResult (users, rows), TWAssign, TWActionResult.

## Build, test, verify

```
  python3 tools/build_twlb.py --snapshot 1.0-lab                 # lab build with real defaults (a snapshot caches tw.env: new name)
python3 tools/pc_import.py Team-Workload-Balancer-1.0-lab.twx
python3 tools/kit_flow_test.py Team-Workload-Balancer-1.0-lab.ids.json "<flow>" '{"data": {...}}'   # every flow over REST
python3 tools/dash_test.py <host> <branch> <cshs>             # playback: tabs, JS errors, failed calls
```

Verified: 8.6.2.20001 lab: 34 open tasks grouped into 7 people / teams, the task list of one team, reassign to a user and return to the team. Dashboard playback: no JavaScript error, no failed call.

## Pitfalls met

* A row click on the person table sets `tw.local.query.who` in the event expression and re-executes the Service Call - the coach data is writable from event expressions.
* Team membership is not part of the task rows: people with zero tasks do not appear (use Team Audit for the members).
